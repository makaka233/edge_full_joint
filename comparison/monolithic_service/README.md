# 整体服务部署与调度适配

`environment.py` 从同一原始配置创建新环境。目录字段依次为 CPU 工作 CU、输入 Mbit、输出 Mbit、RAM、SSD。每类服务的 CPU、RAM 和 SSD 是其阶段和，入口为首段输入，末段输出元数据保留。原用户业务、用户接入和原服务到阶段的映射保留，整体执行目录为十个单阶段链。

Agent-D 使用独立初始化的原 57 维统计模型、八维 Gaussian、EXP026 链路边际定价和 EXP029 滞后优势校准。解码器按实际目录生成 10×32 矩阵并在聚合 RAM/SSD 上检查完整覆盖和库存。在单阶段链上，链路价格只涉及有线入口路径。检查点区分架构。

Agent-S 使用原 Dueling Q、掩码、Double DQN、目标 Polyak 和 Adam 更新。把原 24 列竞争观测中四列下一阶段与一列下一路径竞争去掉，保留包括当前节点 CPU、待处理和在途工作、有线路径耗时、链路积压、合法掩码、聚合 CPU/数据量在内的 19 列。原掩码列保持在位置 7。网络、目标、优化器与回放分别初始化并保存。正常完成的请求产生一次合法调度与一个终止转移。

MonolithicSimulator 复用原即时 REDEPLOY 和连续事件机制。无线入口先执行一次，调度后有线入口按原最短路径逐跳传输，再产生一个 CPU 工作。末段输出字段用于目录，完成时遵循原仿真的请求语义。两种任务粒度会影响共享 CPU 的调度轨迹。CPU finish_pf 的工作量正则参考固定为原目录最小阶段工作量。统计中有线工作以 Mbit×跳计，平均每个到达请求的实际有线服务量包含最后一次排空。

`training.py` 适配原 episode、update 的调用及独立 checkpoint。保留原队列终局、D 校准、S replay 和学习更新公式。`test_comparison.py` 执行聚合、库存、流量、容量、掩码、请求配对、参数独立与恢复训练的真实回归。
