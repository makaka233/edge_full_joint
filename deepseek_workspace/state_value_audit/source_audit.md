# Agent-S 24 维观测源码审计

本文只审计当前源码，不修改主工程。观测由
`edge_d/_engine/edge_rl/physics.py::Simulator.observation()` 生成，并由
`edge_s/agent.py::resource_advantage()` 用于资源先验 Q。

## 已直接提供

- 当前请求阶段、计算量和输入/输出需求。
- 节点 CPU 容量、当前 CPU 作业数、剩余工作。
- 已派发但尚未入 CPU 的节点聚合工作。
- 固定路径上的链路竞争、瓶颈和下一阶段传输估计。
- 当前和下一阶段部署支持集。
- 当前请求已等待时间。

## 可以推断

- 当前所有合法节点的压力可由列 0、1、2、16–19 相对比较。
- 下一阶段局部支持可由列 12–15、22 推断。
- 当前节点与其他候选节点的相对资源时间可由资源先验
  `resource_advantage()` 推断。

## 只能部分表达

- 全 28 阶段部署支持集：观测只含当前和下一阶段，节点压力列只提供部署的聚合结果。
- 单点阶段对特定未来候选节点的强制压力：`node_pressure` 与
  `stage_pressure` 是聚合，不足以恢复完整阶段—节点分配。
- 其他活跃请求的剩余阶段分布：只有节点级 remaining 和 inflight 工作。
- 跨期遗留任务：节点剩余工作包含其物理负载，但无法还原所属请求、阶段和 cohort。
- 请求间共享支持集的重叠：只能从当前/下一阶段和聚合压力间接推断。

## 当前观测没有直接提供

- 其他每个活跃请求当前所在的服务阶段。
- 按阶段划分的在途 CPU 工作（只有节点聚合）。
- 每个 cohort 的剩余截止时间。
- 各 cohort 的请求数、惩罚状态和跨期剩余计时。
- 完整 28×32 部署矩阵对每个未来候选节点的强制计算压力。
- 其他请求与当前请求之间的精确共同瓶颈。

## 资源先验

`edge_s/agent.py::resource_advantage()` 只使用列 0、5、8、16、17、18：

```text
service_time = stage_compute / cpu_capacity
time = service_time + cpu_queue + inflight_cpu + route_queue + solo_wire
prior = centered(-log(1 + time / latency_ref))
```

因此资源先验直接使用当前节点容量、焦点阶段服务时间、节点剩余工作、
已派发未入 CPU 工作和路径竞争；它看不到其他请求的阶段身份和完整未来支持集。

## 结论边界

源码审计只能说明观测中有什么，不能单独证明这些缺失信息会影响动作排序。
必须结合真实状态分叉和反事实收益才能判断状态是否充分。
