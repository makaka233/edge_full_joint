# 完整项目独立研究交接（2026-11-19 修正版）

## 0. 接手时首先确认

这不是只包含 Agent-D 的工程。它含有**完整物理请求系统、Agent-D、Agent-S、真实经验回放、S-only、D-only、BUILD-only D/S 联合训练、跨部署周期 KEEP/BUILD+D/S 训练、评估、原始日志、脚本、配置和测试**。ZIP 内不含训练模型；不得依赖旧 R0–R41 工程或对话。

**真实状态：所有训练器目前是能够执行的研究基线，不是已经证明收敛的算法。** 原 D 构造方法已证实有长序列信用、过早平台、负尖峰和未终止问题；新引入的 S 和 D/S 模块只做了少量真实运行烟测。不能将“恢复训练闭环”写成“联合训练成功”。

本版本纠正上一份 Agent-D 精简版交接中遗漏 Agent-S 和联合训练的范围错误。

## 1. 项目的最终研究目标

异构协同边缘网络（32 节点、52 物理链路、10 类多阶段服务共 28 阶段、12,000 用户），联合学习：

1. Agent-D 长期为每个服务阶段选择 0/1 节点部署矩阵 `X∈{0,1}^{28×32}`，允许复制、减少和重定位副本，按需求选择 KEEP/BUILD 或重新部署时机；
2. Agent-S 为每个就绪请求阶段，在已部署副本之间实时选择节点；
3. 计算和逐跳链路在实时任务竞争下由物理引擎分配资源；
4. 长期保持合理部署成本、低平均任务端到端时延及可控尾部风险，随机初始化后通过深度 RL 获得独立学习收益。

**尚未实现的最终能力：** D 的理想目标 Masked Discrete SAC 或其他可收敛完整矩阵策略，动态学习部署周期长短、真正完整天级长周期训练、可证明安全完成构造、稳定的 D/S 联合收敛。它们是后续研究，而不是本交接包已完成内容。

## 2. 当前正确的物理合同（不可默默修改）

- 32 个异构边缘节点；52 条无向拓扑边，对应有向容量竞争的物理资源；固定最短路；每个节点相应 AP 固定无线共享上行。
- 10 类服务、28 阶段、12,000 用户与独立需求分割（`train/fixed/holdout`）。
- 当前实现总 CPU 为 **366.9185126748571 CU/s**，AP 容量约 **60.7–118.1 Mbps**；当前 CPU 算法为 **`finish_pf`**。这与历史设计意图 7200 CU/s、AP 300 Mbps、CPU 根号 KKT 不同，不能称为已按原参数实现。
- 单期物理评价为 **2 个 6s 观测窗，20s 真实预热，8s 观察尾部**。`censored`=窗口尾部未完成请求，**不等于被系统真实丢弃**；额外惩罚来自当前固定 cost_model。不要因大尖峰而裁剪或删除负 Reward。
- D 的 FINISH 当前默认经过 `rho*<1` 的理想 CPU 承载 LP，这是**当前平均需求下的必要条件**，不是端到端 SLA 充要条件，不提供通用的编辑可终止性保证。

## 3. 程序结构（每个模块的唯一职责）

| 路径 | 作用 | 当前可靠性边界 |
|---|---|---|
| `edge_d/_engine/` | 原事件驱动世界、CPU/链路/无线竞争、S 决策接口 | 固定矩阵/相同请求轨迹物理结果已与旧精简版一致 |
| `edge_d/world.py` | 独立的随机需求；D/S 所需世界；精确 CPU LP | 已核验跨 seed / split 不再共用人口 |
| `edge_d/physical.py` | 唯一真实评价及 Scheduler 注入/转移收集 | 与 D-only 原 Reward 接口兼容 |
| `edge_d/policy.py`, `actions.py`, `rollout.py` | D 从全零编辑矩阵，精确合法 `log_prob`，一次性提交 | REINFORCE 构造仍存在长路径及非终止风险 |
| `edge_d/training.py` | D-only 独立训练及 fixed/holdout | 旧负结果基线 |
| `edge_s/agent.py` | **S 的 Masked Dueling Double DQN、online/target Q、experience replay** | 已验证非法节点不可选，真实转移可训练；独立效果未验收 |
| `edge_joint/training.py` | **S-only / D/S BUILD-only 联合训练** | 双优化器真实运行通过一次短烟测；没有长期收敛证据 |
| `edge_joint/periodic.py` | **宏观 KEEP/BUILD + D 完整构造 + S 调度**；持久化旧矩阵跨期 | BUILD→KEEP 真实验证通过，1 更新烟测通过；未验证长期控制和收敛 |
| `edge_d/plotting.py` | 未平滑训练 Reward/E2E/截尾/S-loss 绘图 | 原始数据不变，不删除失败样本 |
| `configs/` | 当前生效的世界与物理协议 | 修改需版本化物理合同及重新做一致性验证 |
| `tests/`, `scripts/` | 自动测试、交接包完整性核验 | 不代替 64 更新独立性能验收 |
| `runs/archive/legacy/checks/`, `runs/archive/legacy/evidence/` | 本轮真实烟测和历史正负研究证据 | 不参与模型更新/选模 |

## 4. 实际执行过的真实烟测（仅作为闭环验收）

同一源码的原始物理事件仿真，不使用虚构 Reward：

| 实验 | 训练完成 | 起始 Holdout Reward | 最终 last Holdout Reward | 结论 |
|---|---|---:|---:|---|
| S-only, Seed13, 1 更新 | S=2，D=0 | -21.0066 | -31.6814 | S 转移训练可跑；性能退化 |
| BUILD-only Joint, Seed13, 1 更新 | D=1，S=1 | -21.0066 | -17.7616 | 两个网络都实际更新；单检查点改善不代表收敛 |
| 多周期 Periodic, Seed13, 1 更新，2 周期，6s 预热 | D/macro=1，S=1 | -12.9409 | -13.2504 | 同 Env 跨期真实运行；总体退化 |

这些数字是本轮短烟测结果，物理预算和样本量不足以与历史 64-update 结果直接比较。为使有限验证可运行，周期性短烟测使用了**6s 预热而非默认 20s**；该事实在 `runs/archive/legacy/checks/periodic_joint/run_config.json` 的配置中显式保留。真实 **BUILD→KEEP** 同部署矩阵哈希跨期一致的检查也通过，证明 KEEP 分支不仅存在于代码。

另一次 `joint-smoke` 从随机 D/S 初始化的 Reward 为约 **-191.21**，有 930 条实际 S 轨迹，全部合法；说明未经训练的 S 能引发很差的性能，绝不能隐瞒这些负样本或使用启发式暗中替换 Agent-S 动作。

## 5. 历史已验证的负结果与工程缺陷

见 `docs/HISTORY.md`。关键要点：

- ActionQ 在 12 个未见 FINISH-vs-继续编辑测试点对价值方向全部预测错误；同时应说明样本偏向继续更优，不能把这 12 点当成全空间 0% 准确率。
- 仅用真实配对差值的增强学习方向不稳定，曾导致 FINISH 概率过低、编辑循环和未完成。
- 192 张历史结构合法矩阵中 34 张理想 CPU 不可持续，其中 15 张短窗没有报告截尾；说明形式合法性不足和短窗漏检均存在。
- CPU 理想必要条件门控使随机初始布局显著更好，但没有提供收敛证据。
- 历史尝试的 64 D 更新：Seed13 有 60 次完成后无法自然 FINISH，Seed14 只见 57 次完成；虽在固定验证中有后期改善，同时编辑步数大幅膨胀，缺少最后 64 更新独立验收。
- 历史旧环境生成曾错误复用跨种子人口/需求；当前独立需求协议已修正。

## 6. 研究员接手流程

1. 阅读 `README.md`、`docs/MODEL_CONTRACT.md` 与 `docs/JOINT_CONTRACT.md`，核对物理单位和失败语义。
2. 按 `docs/REPRODUCE.md` 安装，先跑 9 项单元回归、`smoke` 和 `joint-smoke`。
3. 用 `s-train --updates 1`、`joint-train --updates 1` 和 `periodic-train --updates 1 --periods 2` 验证真实完整接口；不可把运行成功当作性能有效。
4. 为正式研究按两个种子分别训练 ≥64 个明确定义的更新单位，并给出原始逐条 Reward/E2E/截尾曲线、固定验证、最后独立 Holdout 和 D/S 学习诊断。
5. 优先重新设计 Agent-D 的可学习完整矩阵分布和安全可达性；保留 S 的独立启发式基线对照。重点检查局部 S credit 是否真正降低全局时延，避免调度学习损害整体 Reward。
6. **仅保存 best/last 模型，尽可能保留全部物理日志；失败和未自然终止必须显式记录，不能伪造物理 Reward。**

## 7. 交付内容完整性与现实限制

所有活跃运行路径在当前 ZIP 内，包含 Agent-S、经验回放和联合训练模块，且没有旧训练脚本依赖。交接包不包含 `.pt/.pth`，但重新运行会自动生成模型；历史证据保留经过精简筛选的原始日志和图，**不声称包含曾经所有实验的完整档案**。

本工程能够完整*启动* D-only、S-only、BUILD-only D/S 和多周期 D/S 训练，但并不满足最终论文要求的“已验证 64 GS 收敛”。不存在可以由这份交接材料支持的长期收敛保证。
