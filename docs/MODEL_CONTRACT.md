## 部署结构合法性

`X[k,n] ∈ {0,1}`；对任意阶段 `k`，`Σ_n X[k,n] >= 1`；任意节点 `n` 的各服务镜像资源用量不能超过 RAM/SSD。覆盖从全零开始，覆盖阶段策略可选任意合法 stage-node；编辑阶段可 ADD、REMOVE、RELOCATE 和 FINISH。

当前额外的 FINISH 门控：

\[
\rho^*(X)=\min_{z\ge0,\rho}\ \rho\quad\text{s.t.}\quad
\sum_{n:X_{kn}=1} z_{kn}=D_k,\ 
\sum_k z_{kn}\le \rho C_n
\]

`rho*(X) < 1` 仅说明在当前需求均值、理想计算卸载分配下没有被证明长期不可持续。它**不是**真正多跳通信、排队、启发式调度或尾时延的充分条件，也没有保证有限步可达。

## 真实事件仿真

请求在世界中的到达由可复现 RNG 生成：无线接入、服务各阶段就绪、网络逐跳传输、边缘节点计算，按系统实际资源竞争与任务事件推进。此工程当前采用 `LoadAwareHeuristic` 选择执行副本，不是在联合训练 Agent-S。

必须区分：
- `completed_e2e`: 在统计窗口内完成请求的平均时延；
- `penalized_e2e`: 包含尾部截尾惩罚的指标；
- `censored`: 超过观察尾部未完成的请求数，**不等于永久丢弃数**；
- `reward`: 原定义综合物理评价（含持有和切换成本等）；极端值真实保存。
- `cpu_rho_lower_bound`: 理想 CPU 必要可行性 LP，非真实逐节点瞬时 CPU 利用率。

同一需求窗口短暂超载不意味着立即发生无限排队；持续超载、窗口长度及截尾规则可以造成巨大的负向 Reward 尖峰。必须通过连续工作量、真实时延和尾部指标分解来验证，不能只看 `rho>=1`。

## 训练算法与验证单位

当前 `EditActor` 基线使用 on-policy REINFORCE；每个优化器更新以多个完整部署原始 Reward 减去 leave-one-out 基线。它的“一个 update”与“一天逻辑 GS”不同。完整动作是整张矩阵，不是每个 ADD 算一次宏观时间步。其长轨迹终局信用与构造循环是已知缺陷。

**本次全项目交接补充：** `edge_s.agent` 已提供实时调度 Masked Dueling Double DQN（真实 32 节点合法掩码及 STransition 经验回放），`edge_joint.training` 提供 S-only / D/S BUILD-only 联合训练，`edge_joint.periodic` 提供同一 Env 旧矩阵跨期 KEEP/BUILD 与 D/S 联合训练。已通过短烟测；不代表正式 64 GS 收敛，也不改变上述物理指标定义。

**评价正确的必要条件：** 完整真实轨迹逐点保留、失败与未终止单独统计、固定验证只用于选模、最终 holdout 不用于更新、使用一致物理模型与可比预算、不以漂亮平滑曲线代替独立改善证据。
