# 物理、分配与评价

资源与事件核心在 [原始仿真器](../edge_d/_engine/edge_rl/physics.py) 和 [CPU 分配器](../edge_d/_engine/edge_rl/cpu_allocation.py)。AP 上行活跃请求均分；有线固定路由逐跳，每条有向链路分配与该链路剩余传输工作量平方根成正比。节点 CPU 默认 `finish_pf`，加权对数效用权重向短任务倾斜；可选 `kkt` 按剩余工作量平方根分配。平方根解最小化固定活跃集合和固定速率条件下的剩余完成时间之和，不是共享 NIC 全网优化或完整动态 E2E 最优。事件先结算旧速率，再为新成员集合重分配，保持资源和工作量守恒。现行 CPU 总量约 366.9 CU/s，无线约 60.7–118.1 Mbps。

训练有效预热 20 s（配置基础值为 6 s），两个 6 s 窗口各最多 8 s 跟踪，背景流继续到达。逻辑周期 7200 s，不代表物理实跑。窗口截尾并非丢弃：Reward 计观测到的时延下界并为未完成者额外加 10 s，原目标还计资源持有和切换代价。独立图同时区分完成请求 E2E 与惩罚后 E2E；完成者指标可能有幸存者偏差。原 CPU 理想承载 LP 是资源可行性的必要压力诊断，不保证实际调度和链路。连续压力/排空结果见 [EXP004](../research/experiments/EXP004_allocator_and_censoring/README.md)。
