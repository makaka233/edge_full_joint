# 有界整矩阵策略与训练协议

## Agent-D 与解码

- 输入是现行 `pair_features` 的 19 维 `(阶段, 节点)` 特征，包括计算、存储、阶段需求、区域需求、旧部署和资源占用；分别取均值、标准差、最大值，输入单隐藏层 Tanh 网络。输出 8 维高斯均值；随机初始化，不加载成熟部署或已有权重。池化会丢失细粒度关联，具体配对优先级仍使用节点级需求和资源矩阵，不宣称是图网络。
- 用观测到的预期阶段工作量 `d_k`、节点 CPU `F_n`，解一个连续运输 LP：`sum_n y_kn=d_k`、`sum_k y_kn<=rho_cap F_n`，单节点放不下的边流量为零。`rho_cap` 在全局负载下界与 1 之间由策略选择，若全局负载高于 1，则记录不可消除的超载。目标系数由策略调制的需求加权路由开销、算力、需求/算力和存储份额贡献，加独立解码噪声。流量不是仿真的调度动作；只将正流量支持作为副本起点，真实 S 可选择任意已部署合法副本。
- 若流支持不满足覆盖/RAM/SSD，则同一次解码用覆盖 MILP 得到最小必要覆盖（每个阶段先确保一个副本），放弃该步的 CPU 证书而不拒收或删除样本。随后按条件化 logistic 分数，仅接受阈值以上且仍能放入节点的附加副本。没有人为总数、每阶段副本配额或基于 Reward 的挑选；一次输出一张矩阵。结构合法性最终强断言；不保证任意场景的 CPU 可持续，也不能生成每一种理论合法矩阵（运输支持/回退给出结构先验）。
- 无 ADD/REMOVE/RELOCATE/FINISH 循环；运输求解及有条件的 MILP 不依赖请求未来信息。`cpu_lower_bound` 对实际输出重新测量理想承载，结果仅用于日志。没有 KKT 调参、Reward 裁剪、延期提交或启发式替换学习结果。

## 实际训练

BUILD-only 是情境 bandit：每个提交从独立重置的需求状态开始，没有跨 GS 的旧部署或队列。对同一上下文，采样 `epsilon~N(0,I)`，提交 `z_+=mu+sigma epsilon`、`z_-=mu-sigma epsilon`，共享解码噪声、请求和冻结的 S 版本。反对称得分函数梯度是 `(R_+-R_-) epsilon/(2 sigma)` 对 `mu` 的正向梯度；求导时两支的 latent 视为常量。优化配置明确使用 `build_gradient_scale=2`，与首轮实验等价，并在其后裁剪梯度范数（不裁剪 Reward）。每支边际分布保持正确；共享随机数是方差控制，不保证任何样本收益同向。该表达式数值可为零但微分不为零，故记录真实 `delta`、梯度范数和相同上下文下精确高斯 KL，而非绘制“损失下降”。**没有 learned Q/Critic**，动作信用来自实际配对 Reward；不会外推未评估动作的 Q。用同一矩阵提交方式做独立泛化评估，不用训练损失或合法率替代 E2E。

- `d-only` 固定已有负载启发式 S；`s-only` 固定随机初始化 D 的条件映射（矩阵仍可随需求/解码种子变化），用实际原始转移训练 S；`joint` 同时学习 D 和原 S，每个配对期间两套参数都冻结，更新后 S 版本递增。默认 S 本地 Dueling Double DQN 和原回放，不启用未闭合的额外信用。
- 周期 `periodic` 增加第 9 个潜变量作为 KEEP/BUILD 门，已覆盖时阈值判决，初始强制 BUILD；每个四期轨迹持久化旧矩阵并让 `Env` 推进需求状态。每次对两条共享外生随机数的轨迹进行原始 Reward 的 discounted return-to-go 策略梯度，过去批次的状态无关基线；首次 BUILD 不更新无效门积分，KEEP 不对未用的解码变量赋信用。原 S 在整对轨迹冻结，事后回放更新。物理每期仍重启两个观察窗，未恢复 R12 D80 宏观反事实。
- 每个 `GS` 是一次真实训练矩阵提交；BUILD 配对 64 GS = 32 次 D 更新（除 S-only）；四期周期配对 64 GS = 8 次 D 更新。S 每 2 GS 最多做 4 个更新，批量 64。物理提交、S 阶段决策、仿真秒、墙钟及各自更新数分别计数。仅 `best.pt`（固定 Reward 严格较高才替换）和 `last.pt`。Holdout 在训练及选模结束后才执行；同场景、同随机流比较初始/最佳/末次，仅训练有高斯探索，评估用均值（解码仍使用固定随机流）。

论文背景：Double DQN（van Hasselt et al., arXiv:1509.06461）、Dueling 网络（Wang et al., ICML 2016）、组合策略的 simulation rollout baseline（Kool et al., ICLR 2019）。本工程不复现上述组合网络的解码器或基准。
