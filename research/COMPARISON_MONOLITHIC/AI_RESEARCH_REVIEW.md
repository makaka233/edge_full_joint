# EXP029 多阶段与整体服务架构对比

## 研究口径

以 EXP029 五种子正式执行提交 `9c4034f9b7154a592c0849eafa449d23c360814d` 及报告为参照，在现有工作树建立 `comparison-monolithic-service`。本对比的改动位于新增比较模块。多阶段端直接调用原 EXP029 形态的 adaptive_runner.train。标准算法为 Gaussian REINFORCE、链路定价、滞后优势基线、Masked Dueling Double DQN、原 Replay 与原训练时钟。两组各自从随机参数开始。

实际物理配置为 32 节点、52 条无向链路、10 种服务、28 个原串行阶段、12,000 位用户，基准全网 CPU 从配置逐节点相加为 **366.9185127 CU/s**。整体服务的 10×32 动作满足全覆盖与原 RAM/SSD 容量约束。原目录字段依次为 CPU CU、输入 Mbit、输出 Mbit、RAM、SSD，CPU 和 RAM/SSD 分别求和，无线入口取首段输入。末段输出量在目录中保留，完成时遵循原引擎语义。结构差异包括原子 CPU 工作粒度、一请求一次节点选择、完整副本共址和内部有线通信消失。两侧使用相同的 finish_pf 正则参考、逐有向链路 KKT、原拓扑、容量、最短路与费用。资源等价矩阵的实际 RAM/SSD、持有和切换费用已逐项对账。

两组训练用同种子、同原自然分布、同请求、同真实 GS 及 D/S 更新时钟。相同形状的 D 可获得相同随机初值，张量、优化器和 replay 互相独立。整体服务 S 的输入适配为 32×19，原多阶段为 32×24。移除的是无适用语义的下一阶段字段。评价冻结权重，在共同独立需求下改变单一物理因素，按 last 出主图，另存 best 对照。固定权重下允许 D 在每期重新解码部署。 [EXP029 原报告](../EXP029/AI_RESEARCH_REVIEW.md) · [注册因素与预算](../../comparison/experiment_matrix.json)

## 三种子 512 GS 独立实验

每个种子两臂均从随机初始化完成 512 个真实业务期、64 次 D 更新和 4,096 次 S 更新。两架构逐期请求流及固定验证同流。六组训练各生成 512 张不同矩阵，每张均覆盖全部服务或阶段。三个整体服务组实际调度次数 262,529、263,841 和 258,867，与同组到达数相同；对应多阶段为 735,701、742,061 和 725,757。整体服务各组训练墙钟 284–294 秒，多阶段 565–579 秒。墙钟仅对应本次运行。

**已有联合学习证据，长训收敛仍待验证。** 三个整体服务种子的固定验证最佳点均为 GS512，且各自优于 GS448；训练中间有回退。相同架构内随机初始到训练末尾的大幅改善及实际 D/S 参数更新支持学习能力。两架构在 GS512 的横向优势还包含整体服务任务粒度、内部流量、资源占用和少做调度决策的结构影响，当前数据无法分解各因素的贡献。

Seed13 仍有初始风险。GS4 的原始 Reward 为 −20.7601，惩罚后 P99 为 11.138 秒；当期 516 个请求、观察截尾 0、全网 CPU 提供负载为 0.189，但最忙 CPU 利用率接近 100%，峰值并发 21，期末剩余计算 46.56 CU。该期发生于首次 D/S 更新前。这支持局部 CPU 拥塞诊断，现有日志不足以在同一历史状态单独归因 D 与 S。Seed13 整体臂的最差 5% Reward（26 期）为 −7.893，低于多阶段的 −6.721；另有 3 个观察截尾，终局未完成为零。Seed16/17 的整体臂最差 5% Reward 均优于多阶段。

### 同预算冻结评价

两组各自的 best 和 last 在三种子都指向 GS512，因此冻结结果去重后为 13 个物理条件 × 2 条共同外生轨迹 × 3 个种子，共 **78 个配对单元**、每种架构 1,244,754 个到达请求。组间均无观察截尾、终局未完成或永久丢弃。整体服务在 78/78 个单元提升 Reward、降低请求加权完成 E2E 及实际有线传输量；惩罚后 P99 为 77/78 改善。唯一 P99 回退是 Seed16、中间数据 0.5 倍的场景 2975210114，从 778.420 增至 779.896 ms。两条轨迹在不同种子和条件上复用，78 个比较不能解释成 78 条独立轨迹。

## 下一步只长训整体服务

历史 EXP029 校准臂五种子的 best、last 与完整恢复状态均可读取，来源是 `9c4034f9b7154a592c0849eafa449d23c360814d`，五组均为 GS5000、625 次 D 更新及 40,000 次 S 更新。对多阶段 pilot 的 Seed13/16/17，核对与历史训练前 512 GS 的请求哈希、矩阵、原始 Reward、完成和惩罚时延、S 调度及 D 均值均逐期一致。`mature` 只训练整体服务，三个已有种子复制完整 GS512 恢复前缀至新输出后继续，新增 Seed14/15 从随机初始化开始，总预算一致。

```powershell
$env:OPENBLAS_NUM_THREADS="1"; $env:OMP_NUM_THREADS="1"; $env:MKL_NUM_THREADS="1"; python -m comparison.run --suite mature --stage train --workers 5
```

同一命令用于恢复。结束时生成逐 GS 原始图、固定验证曲线和学习汇总，先审查末两个千期区间、五个种子的固定验证趋势、best/last 差距、最差 1%/5%、极端负峰和积压，再决定何时执行新共同 Holdout。评估时使用同预算的历史 EXP029 与新整体服务模型，`last` 为主、`best` 同时报；评估后再决定是否有成熟架构优势。续训分叉已通过两回合连续对照和原始前缀保护测试；整体服务五种子 5000 GS 尚未启动。

## 输出、复现与下一步

在项目根目录运行：

```powershell
$env:OPENBLAS_NUM_THREADS="1"; $env:OMP_NUM_THREADS="1"; $env:MKL_NUM_THREADS="1"; python -m comparison.run --suite pilot --workers 6
```

按原命令续跑。独立评价可用 `--stage evaluate`，已有结果可用 `--stage report`。pilot 为 Seed13/16/17，每个架构每种子 512 GS、64 次 D 和 4,096 次 S 更新。主评价包括两个独立未来、24 个连续期。16 个因素水平中四个自然基线等价，复用同一冻结结果。两个外生轨迹对训练种子共享，汇总按种子和流分别输出。结果包括请求量、训练更新、墙钟、P95/P99、最差 1%/5%、实际存储、CPU/有线利用与积压。副本分别报告原每阶段副本或每服务整体副本，也报告多阶段全链共址位置数作为存储结构描述。

原数据保留在 `runs/results/monolithic_service_comparison/`。协议保存物理配置和因素表哈希，每次训练与评价的记录含实际源码 SHA，冻结结果校验模型文件指纹。正式冻结结果由程序出图。四张短测图每个因素只有一个干预水平，图中的数值仅验证工程接口。
