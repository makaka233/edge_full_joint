# EXP023 · 五种子 5000 GS 固定重部署

在 EXP019 瞬时矩阵切换基线上验证更长训练及跨种子稳定性。库存协调高斯 Agent-D、Adam、原 Masked Dueling Double DQN、业务负载和物理设置沿用基线。五个种子分别从随机初始化开始。每个种子训练 625 个 episode，每个 episode 包含 8 个 24 秒业务期，共 5000 个在线 GS。固定验证每 8 个 episode 执行一次，末次 GS5000 再执行一次。基线源码见 [EXP019 双种子长训提交](https://github.com/makaka233/edge_full_joint/commit/7681e015f0755f8dbbfd44b490f10d495f7cf130)，实际运行提交记录在各种子的 `manifest.json` 中。

## 启动与恢复

在项目根目录的 PowerShell 中执行以下一行。五个种子依次训练，全部达到目标后，程序自动完成各自 `best`、`last` 和相同 `last` 权重的固定动作对照，使用 EXP019 的三个自然负载 Holdout 场景。

```powershell
python -m edge_d.cli adaptive train --experiment EXP023 --seeds 20261113 20261114 20261115 20261116 20261117 --macro-mode redeploy --episodes 625 --periods 8 --period-seconds 24 --eval-every 8 --evaluate-after --prefix ".\runs\results\EXP023\instant.redeploy.long5000"
```

中断后在同一指令末尾追加 `--resume`。程序跳过已完成的训练，继续未完成的训练，再执行独立评估。

## 证据位置

所有产物写到 `runs/results/EXP023/`。公共前缀后加 `.seed<seed>`，例如 `instant.redeploy.long5000.seed20261113.train.jsonl` 和 `instant.redeploy.long5000.seed20261114.holdout.jsonl`。每种子的 `train.jsonl`、`updates.jsonl`、`fixed.jsonl`、`holdout.jsonl`、`best.pt`、`last.pt` 和 `resume_latest.pt` 均使用自己独立的前缀。

## 正式结果

五个种子均完成 **625 个 episode、5000 GS**。共核对 25,000 条在线、6,400 条固定验证和 480 条独立评估记录。每种子 D 更新 625 次、S 更新 40,000 次、宏观策略更新 0 次，价值头更新 625 次。每个种子的 625 个 episode 均记录到 D、S Online 和 S Target 参数变化。每种子业务逻辑时间 120,000 秒，另有 5,000 秒终局排空。训练墙钟合计 342.8 分钟，包含固定验证。

五份训练清单一致记录 `72326616ce0940f6005682af37d2492d24ad51e4`、随机初始化、瞬时切换、固定 REDEPLOY，均标记 `dirty=true`，清单没有保存当时的工作区差异。恢复点、日志偏移、最优与末次模型投影、固定选模和优化账本均已核对。种子 20261113、20261114 的前 3000 GS 与历史 EXP019 的请求流、部署、Reward 和逐请求时延全部逐点一致。剩余三个种子提供新的随机轨迹。最大工作量守恒误差 `1.66e-10`，最大容量误差 `5.68e-14`。

### 在线 Reward、时延与尾部

E2E 按请求汇总，单位为秒。Reward 按业务期汇总，最差 1% 和 5% 每种子分别取 50 和 250 个实测周期。25,000 个在线 GS 合计 12,669,548 个请求，全部在各自观察截止前完成，在线截尾、终局未完成和永久丢弃均为 0。固定验证随机初始化的七个严重周期保留在 GS0，之后所有固定检查点均为零截尾。

| 种子 | 在线平均 Reward | 最差 Reward（GS） | 最差 1% / 5% | 平均 E2E / P99（秒） | Reward ≤ −20 | 训练墙钟（分钟） |
|---|---:|---:|---:|---:|---:|---:|
| 20261113 | −4.587 | −15.390（1308） | −8.047 / −6.669 | 0.438 / 1.108 | 0 | 72.85 |
| 20261114 | −4.393 | −19.320（7） | −7.207 / −5.893 | 0.416 / 0.868 | 0 | 66.95 |
| 20261115 | −4.276 | −26.745（15） | −6.666 / −5.450 | 0.410 / 0.810 | 1 | 65.25 |
| 20261116 | −5.378 | −13.318（1779） | −10.535 / −8.705 | 0.535 / 1.557 | 0 | 66.10 |
| 20261117 | −5.170 | −9.764（4） | −8.105 / −7.194 | 0.502 / 1.215 | 0 | 71.63 |

唯一在线严重周期为种子 20261115 的 GS15，真实平均 E2E 2.663 秒，P99 10.834 秒。全网 CPU 提供负载仅 0.139，节点 31 利用率 96.9%、峰值并发 55、期末尚余 40.52 CU 待处理。整体积压从 2 增至 60。最高有向链路利用率为 40.5%，CPU 理想可达负载为 0.433。该记录支持局部 CPU 排队解释，仍需同流干预来分离部署与调度责任。种子 20261116 没有阈值以下的周期，最差 5% 却是五种子中最差，单一阈值无法概括尾部风险。

### 五种子等权分段趋势

以下数值使用每个分段的全部原始记录。先分别计算种子的 Reward、请求加权平均 E2E 与请求级 P99，再对五种子等权取平均。表中 P99 为五个请求级分位数的平均。趋势图中的 P99 曲线则从每个业务期的 P99 按 64 GS 窗口生成，两者的统计口径不同。

| 在线区间 | Reward | 平均 E2E（秒） | P99（秒） |
|---|---:|---:|---:|
| GS1–512 | −5.319 | 0.523 | 1.266 |
| GS513–1024 | −5.079 | 0.496 | 1.196 |
| GS1025–2048 | −5.129 | 0.501 | 1.288 |
| GS2049–3000 | −4.592 | 0.442 | 0.948 |
| GS3001–4000 | −4.426 | 0.423 | 0.873 |
| GS4001–5000 | −4.429 | 0.423 | 0.854 |

从首个 512 GS 到最后 1000 GS，五种子的 Reward、均值与 P99 都改善。主要学习收益在 GS3000 前后已经出现。最后两个 1000 GS 区间总体 Reward 和均值近乎持平，但种子 20261116 仍改善，种子 20261117 的 Reward 从 −4.796 回落到 −5.116、P99 从 1.060 升至 1.145 秒。五种子的固定验证 Reward 在 GS3008 和 GS5000 分别为 −4.284、−4.278，平均 E2E 为 0.407、0.401 秒。相同固定场景和业务期内，两个检查点之间仍平均改变 65–170 个阶段—节点位置。结果支持平均性能趋缓，部署分布稳定性仍缺证据。

### 固定验证选模与独立 Holdout

`best` 按该种子的固定验证净 Reward 选出。表格每格依次为净 Reward、真实完成请求平均 E2E、P99。每种子每臂评价三个自然负载场景、24 个业务期，各臂同请求流。每臂合计 63,413 个请求，零观察截尾、零终局未完成、零永久丢弃。

| 种子 | 固定 best GS | 独立 `best` | 独立 `last`（GS5000） |

| 20261117 | 3840 | −4.556 / 0.435 / 0.789 | −5.081 / 0.486 / 1.192 |

五个种子的 `best` 在三个独立指标上均优于 `last`。末次平均净 Reward 低 0.196，平均 E2E 多 18 ms，P99 多 118 ms。种子 20261117 退化最大，P99 多约 403 ms。用同一 `last` 权重改为首期后 KEEP，种子 20261113、20261114 的平均净 Reward 分别提高 0.116、0.087。后三个种子则由固定 REDEPLOY 占优。自然负载结果支持 EXP019 基线的学习收益，暂不足以证明五种子均稳定收敛或通过持续高负载验收。
