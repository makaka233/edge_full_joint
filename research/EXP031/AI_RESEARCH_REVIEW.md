# EXP031 · Seed16 部署与调度的冻结归因

**冻结结论。** 历史事故和 16 条新轨迹均支持 Seed16 退化主要随 Agent-D 权重变化，新的 S 在平均 Reward 和完成 E2E 上缓解了损失。通过的是 D/S 归因门槛。现有物理证据尚未确定应修改哪一项学习机制，保留 EXP029 滞后优势校准，暂不选定 EXP031 新候选。

## 项目与版本

原系统为 32 节点、52 条无向物理链路、10 类服务的 28 个串行阶段和 12,000 用户。24 秒业务期内由原离散事件引擎连续推进，保留 CPU finish_pf、有线平方根 KKT、固定最短路径、原始容量、Reward、持有和切换成本。Agent-D 生成八维高斯潜变量，经 EXP026 链路边际定价解码出合法 28×32 矩阵，固定瞬时 REDEPLOY。Agent-S 使用原 Masked Dueling Double DQN，于在线 episode 末更新。EXP029 从当前优势扣除以过去批次更新的期位 EMA，保持原 Actor、探索、价值头、物理约束和双智能体优化。

EXP029 五种子各 5,000 GS 相对 EXP028 将平均 Reward 从 −4.6822 提高至 −4.2624，完成 E2E 从 452.12 降至 402.63 ms，惩罚后 P99 从 1.0861 降至 0.8135 秒，严格独立验收 26/40。EXP030 的冻结对照显示，Seed13 单独换 D 后 E2E 增加 25.20 ms。随后负载条件校准的 512 GS 有界续训严格通过 23/48。其 Seed16 last 在共同独立评价中平均 Reward 降低 0.07115，E2E 增加 7.96 ms，P99 增加 17.52 ms。原 Seed13 因果结论不能直接转用于 Seed16。 [EXP029 交接](../EXP029/AI_RESEARCH_REVIEW.md) · [EXP030 交接](../EXP030/AI_RESEARCH_REVIEW.md)

本地新分支为 `exp031-deployment-generalization`，从 EXP030 报告提交 `4cc23362f154ea7417668daccb559d2cf6dfd220` 分出。该提交与 EXP030 续训源码 `bfc11b5f9393d2dcd7d55bf1d67bda4e95a97f91` 的差异只涉及报告与绘图。两套 Seed16 GS5512 模型的清单核对了从 EXP029 真实 GS5000 恢复的来源，EXP029 训练提交为 `9c4034f9b7154a592c0849eafa449d23c360814d`。两套 `last.pt` 权重与各自恢复文件一致，日志偏移对账，累计 689 次 D 和 44,096 次 S 更新。历史档案和当前权重均由本地证据复算。正式执行入口将模型 SHA256、事故来源、Git 提交及轨迹协议写入 `runs/results/EXP031/frozen.protocol.json`，每条轨迹同时记录实际运行提交。

## 冻结协议和判定

|四格|Agent-D|Agent-S|
|---|---|---|
|A|EXP029 续训 GS5512|EXP029 续训 GS5512|
|B|EXP030 续训 GS5512|EXP029 续训 GS5512|
|C|EXP029 续训 GS5512|EXP030 续训 GS5512|
|D|EXP030 续训 GS5512|EXP030 续训 GS5512|

历史轨迹使用归档原协议的确定性 D 均值与贪婪 S，从原空队列复现。A/D 的逐期部署、潜变量、请求级时延、Reward、CPU/有线/无线工作、积压与成本必须与归档逐项一致。新轨迹按自然、突发、持续 0.55、持续 0.70 每档注册四条，每条用一个共同自然期形成合法旧矩阵和期初未完成工作，再连续计分 24 期。四格的事件队列、已派发阶段、随机请求流、解码随机源与高斯创新量成对固定，S 贪婪，权重冻结。每条轨迹独立成对对比，同条队列后续按策略真实分化。配对的 A/C 和 B/D 各自必须具有相同部署矩阵。历史与新轨迹使用不同 D 探索模式，跨两套评价的差异不能单独归因于需求或探索。

按独立请求轨迹统计 B−A、C−A、D−A、D−B−C+A，并报告另一个 S 或 D 条件下的边际效应。按四档负载分层做 20,000 次配对 bootstrap。联合 Reward 或 E2E 的 95% 区间必须落在不利侧，主导分量须同向、绝对效应大于其余独立分量和交互。D 或 S 单独归因为主时，换另一个智能体的权重后也须维持不利边际；主要指标结论冲突时不做定向修改。P99 单独恶化会报告，不能替代主要指标上的归因。通过此筛选只确定深入诊断的模块。只有进一步查清状态、训练覆盖或信用机制，才选择唯一算法候选。

### 学习机制与是否升级

- **权重到布局的影响已观察到。** 新轨迹的首个计分期，A/B 的输入、出发队列和高斯创新量一致，仅替换 D 权重，潜变量均值的 L2 差平均为 1.971，布局相差 23–84 位、平均 57.69 位。全程平均相差 59.82 位。首期完成 E2E 平均增加 6.46 ms，个别轨迹改善。该证据支持权重引起的布局变化，尚未测出小扰动下解码器各阶段的局部敏感性。
- **状态混叠真实存在。** A/C 和 B/D 的 768 对预决策观察的 57 维输入完全一致，590 对的 CPU 或有线队列不同。持续 0.55 第 1 条的记录期 8，节点 27 的期初 CPU 工作为 4.045 对 0.080 CU。持续 0.70 第 2 条的记录期 20，有向链路 8→0 的期初工作为 8.552 对 0.531 Mbit。两项期号均含前置期。尚未验证同一组合法部署在这两种队列上会发生稳定的性能排序翻转。
- **负载覆盖与信用漂移均值得区分。** 训练未覆盖持续压力，D 效应在压力下更大，但自然档的 Reward 和 E2E 同样下降。负载条件校准确实改变了现有 Actor 的更新和布局，重建排除了已核对的时间索引、对数概率及 Adam 状态错误。现有证据无法在观测缺失、训练覆盖和策略更新之间选出一种经物理反事实验证的最小修正。

**判定。** 预注册的模块归因为 D。保持 EXP029，暂不升级算法。下一项区分实验是选取同 Actor 输入、同旧矩阵、不同期初队列的配对状态，在固定同一 S 与请求流下交叉评价两张预先约定的合法矩阵，检验同一组部署的 Reward/E2E 排序是否稳定翻转。只有证明队列信息会改变部署选择的真实收益，才推进状态补全。
