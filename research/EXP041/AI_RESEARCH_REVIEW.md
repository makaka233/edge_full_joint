# EXP041 随机初始化与冷启动 Reward

## 研究结论

**保留现行资源先验 DDQN，结束本轮冷启动修改。** 在五种子、80 个 GS0 固定验证期与 80 个真实在线初期 GS 中，现行方案均为 **0 次 Reward ≤ −20、0 次观察截尾**。新自然请求的 20 个配对期中，随机初始化完整 Q 与仅先验同样无严重期。旧随机 Q 的灾难主要来自局部派发集中，导致排队及失败惩罚同时放大。现行完整 Q 的随机残差确实会改变少数动作，新状态上的净收益很小且方向不一致。当前证据支持资源先验对冷启动的直接物理收益，尚不足以支持修改 D 初始化或 S 残差参数化，也尚未证明残差能够稳定超过先验。

## 程序与物理口径

使用正式 Proposed v2。32 个异构节点，52 条无向链路对应 104 个有向资源，3500 个固定接入端点，10 类服务的 28 个串行阶段相对旧 EXP029 使用双倍 CPU 工作量。仿真沿用 24 秒期、完整 28×32 瞬时 REDEPLOY、原 RAM/SSD 合法性、固定最短路、CPU finish_pf、有线平方根 KKT 与跨期队列。D 为 Gaussian Actor、链路定价解码和滞后优势校准。S 原 Masked Dueling Double DQN 逐 GS 更新。资源时间先验由当前候选 CPU 计算、已排队及在途工作和有线路径估计构成，按合法节点中心化。实际选取合法节点的 \(Q_\theta+Q_{\rm prior}\) 最大值，训练仍有原 ε 探索。先验在在线和目标 Q 中使用同一公式，随机残差保持可训练。[S 实现](../../edge_s/agent.py) · [部署训练与 Reward](../../edge_joint/adaptive_training.py)

## 实验前登记

以 EXP040 正式提交 `f26b8ccf178455d0f69047945cf7792362830045` 为源码起点。EXP040 的 LaBER 候选只作背景。当前训练参考为 EXP037 引入、EXP038 延用的资源时间先验 DDQN，搭配原回放及逐 GS 的 S 更新。核对五个种子 `20261113`–`20261117` 的历史完整训练记录，单列 GS0、GS1、GS1–8、GS9–16 和 GS16 固定验证。历史无先验随机 Q 作为同流冷启动参照。GS0 聚合每种子既有两条固定场景各 8 期。归因只需要重跑其第一条，固定编号 `19001`。

- 同一随机初始化 D 和完全相同的矩阵序列、请求及跨期队列规则，对照未训练完整 Q、仅先验、合法均匀调度。在线首八期重放使用实际记录 ε。GS0 和新独立自然场景用贪婪合法 Q，均匀调度是冻结诊断专用分支。反事实允许后续队列因调度自然分化。
- 每训练种子另登记一条新人口与自然请求轨迹，连续四期。初始完整 Q 一次生成随机 D 部署序列，其余分支复用同序列。此处额外用真实 GS16 S 权重评估早期学习、锁定同一个 D。各冻结臂不更新任何参数。
- 严重负峰按原约定 `Reward ≤ −20`。逐期复算原 Reward 的完成请求时延、截尾已等待时长、额外失败惩罚、持有及切换贡献。核验完整矩阵、预计 CPU 负载、单副本阶段、实际工作量、请求守恒和同流。理想 CPU 承载 LP 衡量给定估计需求下的算力可分配性，实际时延和排队由事件仿真衡量。
- 只有当前资源先验组出现可重复的真实冷启动严重故障，并且能够归因到具体部署参数化或 S 价值机制，才实施一项修复。若现有先验已经缓解严重故障，保留正式算法。只在新修复通过冷启动后才进入 GS64，后期 Replay 和压力覆盖不属于本实验。

## Reward 分解与 CPU 因果链

原 Reward 为负的时延与部署成本之和。对当期 \(N\) 个到达请求，完成部分为 \(10\sum_i T_i/N\)。截尾部分为 \(10\sum_j(t_{\rm cut}-t_j)/N\) 与额外失败惩罚 \(10\sum_j c_{\rm fail}/N\)。再计入原持有、切换成本。现行 GS0 按期平均的分项为完成时延 **8.6083**、截尾等待 **0**、失败 **0**、持有 **0.0898**、切换 **0.0485**，合为 −8.7466。约 −9 的评分与不到一秒的请求时延相符。所有逐期分项均按原公式校验至绝对误差 `1e-8`。

- **旧随机 Q 的首八期最差例，Seed16 GS3。** 同一矩阵的理想 CPU 负载下界 \(\rho^*=0.6531\)，6 个阶段为单副本。节点 8 的原 Q 峰值并发 224、期末积压 448.32 CU，资源先验组峰值并发 5、积压 0 CU。原 Reward −112.457 中有 64.554 截尾等待与 32.400 额外失败惩罚。换成资源先验，同流 Reward −10.625、惩罚后 E2E 从 11.229 秒降至 1.046 秒、截尾从 162 降至 0。在线 GS3 两组继承的队列和 S 已有更新可能不同，完整冻结实验另验相同起点的贡献。
- **旧 GS0 的最差例，Seed14 场景 19002 第 8 期。** \(\rho^*=0.6898\)，旧随机 Q 在节点 8 达到 396 并发、613.86 CU 期末积压。相同矩阵改用现行完整 Q 后，Reward −266.162 → −10.105，P99 41.606 → 2.230 秒，截尾 466 → 0。两臂当期最大有线余量同为 2.59 Mbit。变更前后均为初始随机参数，跨期积压随调度演化。
- **新轨迹对照，Seed17 第 3 期。** 阶段 10 只能在节点 25 执行，预计需求 9.68 CU/s。相同矩阵 \(\rho^*=0.7206\)，节点容量每期 387.38 CU。合法均匀调度使节点 25 按期初、注入、处理、期末计为 158.11、463.12、387.38、233.85 CU。现行完整 Q 同口径为 2.89、354.19、352.96、4.11 CU。两臂有线期末余量均为零，Reward −91.576 → −10.343，惩罚后 E2E 9.140 → 1.017 秒，截尾 145 → 0。既有单副本负载与可分流的其他任务共享 CPU，均匀选节点会放大该竞争。

历史 GS0 与首八期的最大理想 CPU 比例分别为 0.760 与 0.700，新自然场景最大为 0.831。LP 用当前预期工作量，在矩阵支持集内允许理想分流，因此只能说明这批布局在平均计算负载假设下可承载。上述故障由实际调度和队列演化证实。受审的历史灾难主要支持归因 B，当前常见的负评分支持 D。完整矩阵可能在其他负载下成为瓶颈，当前样本未发现支持修改 D 初始化的严重期。[全部 93 条严重期、矩阵、支持集、账本和分项](../../runs/results/EXP041/severe-periods.jsonl)

在初始完整 Q 自己访问的状态上，加入随机残差改变了固定验证 **411/54015** 和新自然流 **239/29937** 次贪婪首选节点，分别为 0.76% 和 0.80%。新自然流的完整 Q 相对仅先验平均提高 0.016 Reward、降低 1.6 ms 完成 E2E，同时 P99 增加 32.1 ms，五个种子中三组 Reward/E2E 双改善。换入 GS16 S 后，与新流同 D 的仅先验相比，五个种子的 Reward 和完成 E2E 都略差，贪婪分歧增至 **869/29937**。当前数据证明先验的冷启动作用。学习残差的独立增益仍未建立。

新独立实验限于五条四期自然轨迹。压力口径复用已有 EXP037 同流结果。GS16 持续 0.70 相对旧 Q 的 Reward −13.482 → −12.768、E2E 1.334 → 1.263 秒，并且无截尾。该批结果每负载只有一条独立外生流。EXP040 LaBER 的 Seed15 高压失败继续保留为单独风险，本轮算法保持原样。未重新开展压力采样、运行新 A/B 训练、扩展至 GS64 或写新模型。
