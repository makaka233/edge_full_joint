# EXP056 双智能体学习贡献、严重负峰归因与续训

**本报告汇总五种子正式续训、双智能体冻结消融和 Seed14 负峰归因。** 在 GS504 的 20 条配对消融场景中，成熟 D 提供主要收益，成熟 S 提供幅度较小、存在种子差异的额外收益。联合成熟组在 16/20 个场景同时优于三个对照的 Reward 与完成 E2E。Seed14 GS131 由节点 0 的 CPU 工作集中和跨槽积压放大。GS1008 的独立评价、固定验证和在线风险见第 4 节。

## 3. Seed14 的 GS131

**直接原因是节点 0 的 CPU 注入严重超过服务能力，已有积压跨槽保留。** 事故在 episode 17。GS130 节点 0 已有 232.49 CU 槽末积压。GS131 全网提供负载为 0.8166，期望到达率为 44.337 请求/s。节点 0 注入 1261.38 CU，服务 324.03 CU，饱和服务约 13.50 CU/s。账本为 232.49 + 1261.38 − 324.03 ≈ 1169.85 CU。节点 0 收到 503/2708 次阶段调度（18.57%），约占全网 CPU 容量 3.68%。该节点调度占比从 GS129 的 3.19% 升到 GS130 的 10.78%。GS131 槽末 608 个在途任务中，562 个在节点 0 的 CPU 队列。最忙有向链路利用率为 28.62%，最大有线积压 3.025 Mbit。有线竞争无法解释 CPU 积压的数量级。

GS131 共 1053 个请求，456 个在各自评分截止时未完成，且这 456 个之后均完成。使用原到达 RNG 重建请求，八槽请求哈希均与旧账本一致。GS131 的截尾集中于服务 3（145）、6（92）、5（76）、4（54）、0（51）和 9（38），编号从零开始。原账本没有这些请求的逐阶段执行事件，无法确认每个请求的实际卡住阶段。817 个截尾为整个种子累计，均来自本 episode；25 个终局未完成发生于 GS136 尾窗结束。GS137 Reward 恢复到 −9.478，物理队列已按新 episode 重置，故没有在同一条连续轨迹内观察到故障队列完全恢复。

- 用真实 Gaussian 潜变量与原解码键精确重建八槽矩阵。GS131 矩阵与上槽相差 138 位，共 75 个副本，最大节点 RAM/SSD 占用率为 99.15%/99.04%，节点 0 为 98.52%/69.48%。GS130 的节点 0 托管单副本阶段 15，期望工作率约 5.05 CU/s。GS131 的节点 0 托管阶段 0、11、13、16、19、26，六个阶段均有其他合法节点。此前已派发任务按原语义保留。
- 在固定当槽布局下，用线性规划将各阶段期望工作量分给其可用节点，得到最小的最大节点理论利用率。GS130 为 0.7725，GS131 为 0.8264。该理想模型允许连续分流，且忽略有线路径、阶段先后、随机峰值和已有队列。结果削弱了以全网 CPU 短缺或 GS131 单副本强制派发解释事故的假设。
- 原 Reward 可由惩罚后 E2E 13.9791 s、持有 0.11147、切换 0.06061 对账。八槽最大物理工作误差为 3.73e−11。实际调度集中、布局暴露及旧任务继承均有实测证据。当期探索率为 0.1991。随机探索、S 估值、具体 Actor 样本及解码键的反事实贡献仍未分离。

主要物理瓶颈已由原账本定位。没有用近似开局做反事实，也没有重复训练到 GS131。当前没有足够依据修改奖励、调度或部署算法。续训保留严重轨迹并监测是否复现。
