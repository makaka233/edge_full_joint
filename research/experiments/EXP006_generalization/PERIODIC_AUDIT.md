# EXP006 · 周期 16 条尖峰的因果审计

原轨迹按训练时点重建原 DDQN、原 epsilon 与旧布局，两个 seed 全 128 个周期逐点匹配原矩阵、Reward 和请求哈希。8 条真实动作是 KEEP、8 条是 BUILD。用同一旧布局、需求、请求流评价替代动作和启发式 S；首次没有全覆盖旧布局时，不虚构 KEEP 比较。

## KEEP 的过时布局

8/8 个 KEEP 尖峰在本期测得理想 CPU LP ≥1；其中 7 个在前一期已 ≥1，一例从 0.972 跨过 1 到 1.019（种子 13 GS40）。到达强度和各 AP×服务的分布相对前一期 L1 变化约 12.4%–39.3%。这些数据支持“旧布局反复保留，未响应已经存在或新出现的承载问题”，不能把每条都归因于突然换热点。重建的前/后各阶段独立需求/副本可达 CPU 比率和副本数，可在逐记录的 `busiest_stage_capacity_ratios` 查到；这些与全局 LP 不同，不能相加或用来排除阶段间竞争。

同一训练 latent 和请求流，直接用原 BUILD 构造器重建，可让 7/8 个 KEEP 获得更高单期净 Reward，5/8 离开尖峰阈值；对剩余 3 条它并非可靠替代。例：

| 种子 / GS | KEEP Reward / 理想 CPU LP | BUILD Reward / 理想 CPU LP | BUILD 切换费 |
|---|---:|---:|---:|
| 20261113 / 40 | −32.62 / 1.02 | −5.14 / 0.31 | 0.052 |
| 20261114 / 27 | −120.00 / 1.44 | −6.69 / 0.71 | 0.044 |
| 20261114 / 28 | −134.18 / 1.51 | −60.12 / 1.56 | 0.052 |
| 20261113 / 62 | −20.10 / 1.02 | **−65.72 / 1.31** | 0.050 |

费用已计入净 Reward。以上是**一期**差分，不能推出长期频繁重建最优。

## BUILD 与调度

8 条 BUILD 尖峰中，7 条发生在没有全覆盖旧布局的轨迹起始期，因此不能合法 KEEP；另一条的同流 KEEP 离开尖峰阈值。保持矩阵不变改启发式 S，3/8 个 BUILD、1/8 个 KEEP 离开尖峰阈值；其余多数需要部署或物理条件改善。示例：周期 14 GS5 的原 BUILD 约 −61.14，换启发式同矩阵约 −5.73；相反周期 13 GS21 原 −135.56，换启发式仍 −126.98。没有改变门、宏观目标或周期训练。
