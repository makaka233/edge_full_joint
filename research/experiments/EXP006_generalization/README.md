# EXP006 · Reward 尖峰修复能否泛化？

**结论：双修复在三个未见需求种子上显著降低了本次样本的短窗和连续尾部风险；保留实验开关，不升级默认。** “显著”此处指观察到的效果量，不是统计显著性声明。S-only 有单场景非劣性反例，且有限压力样本不证明稀有灾难的总体概率。

## 受控设计

EXP005 的算法、物理容量、CPU 默认 `finish_pf`、有向逐跳 KKT、Reward、统计语义、探索、预算与核心 DDQN 均冻结。核对 177 个 EXP005 原算法、配置与证据文件的 SHA-256。S-only 与 BUILD 联合各用种子 20261113/14、64 GS/臂。原基线、仅库存协调解码、两项联合复用 EXP005 的原始数据和固定最佳 checkpoint；只新训缺失的“仅调度时延先验”臂（256 次）。四臂共覆盖 1024 次训练轨迹，训练同 GS 的嵌套请求流逐条匹配。无 PPO、新门控、新 Reward 或预算延长。

固定策略（epsilon=0）评价种子 20261201/02/03，各用普通、1.5× 并发、区域热点、关键服务集中、短时突发五类。每个训练种子/模式/臂 15 个场景，短窗与连续协议分开；共 240 个端到端匹配对照记录，另有 60 个 BUILD 锁定完整矩阵后换 S 的记录。各记录同时含原短窗 Reward 与 60 秒连续队列；连续跟踪没有重置资源，分箱截尾后还做 30 秒无新到达排空。固定验证只选 checkpoint，不用新需求选模。

## 训练消融：不能用均值替代尾部

单元格为「尖峰数 / 最差 4 点均值 / 最差单次」。四点是每组 ceil(5%×64)；越接近零越好。

| 模式 / 种子 | 原基线 | 仅部署 | 仅调度 | 两项合用 |
|---|---:|---:|---:|---:|
| BUILD 13 | 6 / −84.29 / −123.34 | 1 / −13.19 / −22.95 | 1 / −39.04 / −123.25 | 0 / −6.42 / −7.50 |
| BUILD 14 | 4 / −49.02 / −81.72 | 2 / −27.05 / −56.60 | 1 / −18.48 / −51.50 | 0 / −5.98 / −6.08 |
| S-only 13 | 4 / −52.30 / −121.45 | 0 / −10.86 / −17.44 | 4 / −49.85 / −121.14 | 0 / −6.40 / −6.48 |
| S-only 14 | 2 / −52.71 / −90.11 | 1 / −31.84 / −101.87 | 1 / −32.28 / −86.05 | 0 / −6.04 / −6.28 |

两个修改有各自贡献，但各自都不能替代另一个：仅部署把 S-only 14 的最差单次加剧到 −101.87；仅调度在 S-only 13 仍有四条尖峰，在 BUILD 13 仍能跌到 −123.25。仅调度四组仍有 24/22/19/25 次覆盖回退，没有解决部署 LP 支持的不连续退化。两个能力同时改动才在本次四组均达零训练尖峰，不据此宣称任意环境都零。

## 未见需求：双修复的尾部效应

以下每行合并 15 个场景请求，基线 → 两项合用。E2E 为原截尾惩罚后的请求级均值和分位数；零截尾的场景才等于相应完成者指标。

| 模式 / 种子 | 短窗 mean / P99（秒） | 连续 mean / P99（秒） | 短窗最差 Reward |
|---|---:|---:|---:|
| BUILD 13 | 0.720 / 2.737 → 0.461 / 1.045 | 0.646 / 2.190 → 0.443 / 0.909 | −13.95 → −6.61 |
| BUILD 14 | 0.682 / 3.679 → 0.441 / 1.042 | 0.600 / 2.507 → 0.426 / 0.910 | −14.22 → −6.33 |
| S-only 13 | 0.931 / 6.442 → 0.706 / 5.018 | 0.755 / 4.082 → 0.606 / 2.884 | −27.67 → −19.11 |
| S-only 14 | 0.882 / 6.689 → 0.725 / 5.426 | 0.699 / 4.393 → 0.610 / 3.355 | −22.12 → −19.54 |

四组双修复无固定策略短窗尖峰或窗口截尾；S-only 原始对照短窗截尾 10/9、连续分箱 10/9，均在追加排空后完成，不是永久失败。训练随机探索峰、固定短窗峰和连续队列积压分别报告，不将 0 次门槛事件解释为安全。S-only 14 在 20261201 服务集中情景短窗 P99 小幅恶化约 0.007 秒；另有些场景连续活跃请求峰值增加 1–2 个。虽然整体 P99 和最坏场景 P99 改善，预注册规则要求不忽略个别退化，**不切换默认，也不延长训练来掩盖现有反例**。

BUILD 固定原部署只换联合修复训练后的 S，连续 P99 从 2.190/2.507 变为 1.532/2.307 s；固定修复矩阵只换原 S，仍有 1.651/1.255 s，相比双修复自己的 0.909/0.910 更差。两种受控交换支持部署与调度都有贡献，不过此处交换的是整个固定 S 权重和先验，不把权重效应误作单独的先验效应；仅先验的训练消融是不同问题。

**仅调度先验也具有独立收益，但双修复并非每场景都最好。** 仅调度的 BUILD 连续 P99 为 1.175/0.774 s；后者优于双修复的 0.910 s。仅调度的 S-only 种子 14 新压力评价无 Reward≤−20，短窗和连续协议却分别仍有 6 个截尾（不是同一批请求或重复计数）。仅部署的 S-only 13 虽然短窗平均 E2E 从 0.931 降到 0.906 s，P99 却由 6.442 升到 6.718 s，截尾由 10 升到 12。因此必须报告分位数与截尾，而非单阈值或平均值。

## DDQN 与周期

原核心不改。局部时延先验在 online 和 target 的同一前向函数加入；执行 epsilon-greedy 用增强 online Q 在原掩码上选动作；TD 仍由同 online Q 选下一动作、增强 target Q 估值，优化当前增强 Q，Polyak 只更新原参数。测试实际调用原 `update` 并截取其 online/target 张量，与执行网络一致。

周期的 16 条尖峰为 8 KEEP、8 BUILD；8 条 KEEP 均理想可达 CPU ≥1，仅 BUILD 能将其中 5 条带出门槛，但一次替代 BUILD 更糟。详见 [周期 16 条归因](PERIODIC_AUDIT.md)。一期净 Reward 含切换费用，不能推出长期切换收益。
