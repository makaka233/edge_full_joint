# 宏观决策根因：不要把 KEEP 和 BUILD 一概判定为好或坏

[EXP006 周期 16 条精确对照](../EXP006_generalization/PERIODIC_AUDIT.md) 记录了当时 DDQN、epsilon、短窗请求流和旧布局。8 条 KEEP、8 条 BUILD；8 条 KEEP 的当期旧布局理想 CPU LP ≥1，7 条前一期已 ≥1。同一历史短窗换启发式让 3 条 BUILD、1 条 KEEP 离开尖峰；支持部分调度放大，不是所有 KEEP 都应被阈值触发重建。

| 种子 20261113 | 原动作与对照（原历史短窗，含切换费） | 主要证据 |
|---|---|---|
| GS50 | KEEP −76.00 → BUILD −6.44 | 85 → 0 截尾，旧/新理想 CPU 1.438/0.436；启发式同旧布局仍 −74.60；切换成本 0.047 |
| GS62 | KEEP −20.10，BUILD −65.72 | 0/45 截尾，旧/新理想 CPU 1.021/1.312；上期相对需求 L1 变化 32.1%；切换成本 0.050 |
| GS63 | BUILD −38.87，KEEP −13.75 | 22/0 截尾，BUILD/KEEP 理想 CPU 1.246/0.977；启发式在 BUILD 仍 −38.25；切换成本 0.039 |

附加诊断对所有 16 条以**原四期需求路径及已归档布局**做连续队列跟踪，在尖峰点换为其归档对照布局，之后回到相同原计划。这里使用新同流到达与固定双修复 S，**不是**复跑历史 DDQN/短窗；结果依赖这两项条件。新的记录包含相同需求下的 RAM/SSD、CPU/链路积压、实际截止前后完成及费用。

- GS50：KEEP/BUILD 当期 −76.18/−5.73，后续两期 −188.55/−65.88；先前积压真实传到后续期。
- GS62：短窗中 KEEP 较好；在新连续对照下当期 KEEP/BUILD 为 −50.87/−47.35，但后续 −22.14/−45.92，说明只看当期有时会判反。
- GS63：历史短窗 BUILD 较差，但固定 S、新到达的连续对照中 BUILD/KEEP 当期 −16.27/−29.61，后续 −5.87/−6.45。不能把条件变动后的反转归为单独的解析规则；不改变原尖峰记录。

原因是需求与可达资源共同变化，原新布局本身也不稳定，并且调度和已在途请求相互作用。门上线能看见当期已揭示的需求、旧/拟部署压力和队列；上表的处理效果、未来实际请求和延后完成**只用于事后证据**。[长期反事实](../../../evidence/macro_credit/EXP007/historical_continuations.json) · [信用审计](CREDIT_AUDIT.md)
