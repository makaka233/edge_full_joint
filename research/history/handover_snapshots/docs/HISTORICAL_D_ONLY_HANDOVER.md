# 独立研究员交接说明（必须先读）

> 基准时点：2026-11-19。此文档是当前精简工程的唯一权威入口；无需读取任何旧版压缩包、聊天记录或本地开发路径。

## 1. 接手任务

构建能够在真实异构协同边缘网络中学习 **长期分阶段服务冗余部署** 的深度强化学习 Agent-D。完整动作是 `X ∈ {0,1}^{28×32}`。后续将恢复 Agent-S 按请求/阶段选择副本、计算和有线网络资源竞争以及 D/S 联合训练。核心成功标准是从随机初始化出发，独立 Reward 总体改善、平均端到端时延下降、严重异常减少、长训练表现趋于稳定；单纯排除坏矩阵获得的初始收益**不算学会了部署**。

原来的长序列 Actor 已经历多轮修补，不能证明可靠收敛。本包将其作为基线隔离，仅用于复现实验、物理配对和新算法 A/B 对照。**交接任务不是维护它的历史版本谱系，而是基于可信物理后端替换学习结构。**

## 2. 当前确切实现范围

- **运行基线：** 先补齐 28 阶段覆盖，然后策略自主选择 ADD/REMOVE/RELOCATE/FINISH；内部动作不推进仿真时间，提交整张矩阵。FINISH 默认以理想 CPU 最小最大负载 `<1` 作为必要可行门控。无完整部署候选池、强制补副本、投影或 Reward 筛选。
- **训练：** On-policy REINFORCE + leave-one-out 同需求状态回报基线；每个参数更新默认 4 次真实完整部署和物理评价；没有正统动作条件 Critic、没有 SAC 主线、没有 PPO。
- **评价：** 历史物理模拟器；固定负载感知启发式调度器代替 Agent-S；2×6 秒被观察请求窗与 20 秒预热，尾部 8 秒，窗口内未完成请求按原规则截尾惩罚；能够记录真实 CPU 能力下界，但当前未实现所有负载与链路的安全约束。
- **数据隔离：** train / fixed / holdout 的随机需求流分离，holdout 具有独立人口；`best.pt` 只由 fixed 评价选择；最终 holdout 不参与模型选择。
- **产物：** JSONL 原始训练轨迹、固定验证、holdout、动作计数、梯度、`best.pt`、`last.pt`、未平滑图表、错误。代码和交接包不含模型权重。

## 4. 历史事实：不能被误认为已修复

| 问题 | 证据与当前判断 |
|---|---|
| 原 ActionQ 是否会对单动作正确排序 | 曾在两种子 12 个未见 FINISH/继续配对点出现 12/12 排序反向；不能认为 Q 已可靠学会动作价值 |
| 强化配对监督是否解决训练 | 能拟合已见标签，但独立泛化和双种子真实 Reward 不稳定；强偏好拟合还引起未终止和过载 |
| 是否只需改变动作参数化 | 阶段先选、节点后选的对照双种子退化，故不升级 |
| CPU 不可持续与负尖峰关系 | 历史 192 张形式合法部署有 34 张理想 CPU 负载下界 ≥1；其中 15 张旧短窗没有报告截尾 |
| 物理评价截尾是否等于永久失败 | 不是；120 秒回看见许多超过 8 秒尾部的请求后来完成；当前 `censored` 是评价截尾计数 |
| 门控 FINISH 是否改善随机初始行为 | 是；旧对照约 7/24 训练布局 CPU 不可持续，新门控组 0/24，但这种初始差距不是 Actor 学习 |
| 是否已经证明可持续、可靠终止 | 否；只要未能在 1100 内自然 FINISH，就记录异常而非伪造 Reward |
| 是否通过正式 64 GS 联合收敛 | 否；数据为 BUILD-only 优化器更新，未完成多周期 D/S 联合训练 |

### 最近的长训记录：不得遗漏

`evidence/pg64_seed13/` 和 `evidence/pg64_seed14/` 里保留了真实原始训练轨迹、验证、更新以及错误日志，不含 `.pt`。

- Seed13：已完成 **60 次参数更新**；在计划的第 61 次中出现 `Policy did not FINISH`，因此实验中止，**未完成 64**。固定验证均值 GS0→56 从 `-6.5501` 到 `-5.0215`，E2E 从约 `0.6385s` 到 `0.4676s`，但平均构造动作从约 `89.8` 增至 `306.0`。
- Seed14：可查到 **57 次完整参数更新**（不是 64）。固定验证 GS0→56 从 `-8.2345` 到 `-5.4341`，E2E 从约 `0.8139s` 到 `0.5110s`；构造动作从约 `49.0` 增至 `266.8`。此日志没有可核验的 GS64 最终 holdout。
- 因而不能说策略“始终没有学习信号”，但也**绝不能将固定验证阶段改善等同于完成的双种子收敛**。越来越长的编辑链条和已出现的未终止是严重算法缺陷；独立最终 holdout 与完整 64 次更新尚未通过。
- 这些历史计数来自原始 JSONL 文件，不把 `.pt` 带入新交接包。

## 5. 必须优先审阅的三个基础合同

**物理合同：** 当前复现的 benchmark 总 CPU ≈366.9185 CU/s，AP 60.71–118.07 Mbps，CPU 调度模式 `finish_pf`，而用户最初讨论的目标为 7200 CU/s、AP 每节点 300 Mbps、计算平方根 KKT。这是一个重要的研究建模差异。严禁未经独立对照同时改配置、Actor 和 Reward。

**评价合同：** 20 秒真实预热 + 两个 6 秒请求窗 + 各 8 秒 tail 不是对长期稳态的充分测量。截尾惩罚会放大负峰；没有证明累计积压与真实任务永久失败等价。需要单独做不同负载/观测时长的物理一致性实验。

**动作合同：** `rho*(X)<1` 是在当前平均需求的理想可分配 CPU 模型下的必要条件，没有有限步可达性保证。不能仅靠硬 FINISH 掩码宣称安全的训练算法。Agent 的内部步也不能作为宏观 GS。

## 6. 推荐接手顺序

1. **先运行 `smoke` + 5 个单元测试**，对照历史物理快照（见 `docs/REPRODUCE.md`）。
2. 固定物理配置和 request RNG，重放高载荷布局，量化负载→真实积压→观察截尾→Reward 的因果环节；同时保留原 Reward。
3. 设计新 Agent-D：重点是减少数十/数百步构造、动作条件信用与真实概率更新；可以研究整体矩阵概率模型和组合约束建模，但需通过严格同物理预算对照，不能直接宣称可训练。
4. 初始接受测试：随机策略合法率、终止率、动作分布/概率梯度、未见布局真实物理 Reward 与 E2E。
5. 再做双种子至少 64 个**明确计数单位**的更新/宏观步骤，固定验证与最终独立 holdout；记录原始逐点 Reward、不平滑 E2E、失败截尾、CPU 下界、动作数、训练墙钟。
6. 只有 D 在 BUILD-only 验证独立学习有效后，再研究 KEEP/REDEPLOY 以及 Agent-S 联合训练。

## 7. 验收底线

不使用 PPO、预制完整矩阵候选池、人工副本配额、Reward 裁剪、过滤负样本、事后替换低 Reward 部署，或以约束带来的初始优势冒充学习。任何一项训练/仿真失败须日志化，不能构造一个假的 Reward。结论必须区分“代码执行”“物理一致”“策略实际改变”“独立 Reward 上升”“多种子收敛”，不将前项等同后项。
