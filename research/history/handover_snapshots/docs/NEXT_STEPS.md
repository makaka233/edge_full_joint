# 下一位研究员的优先任务（D/S 全工程）

**不要再重新建设 Agent-S 与联合训练脚手架：它们已经在 `edge_s` / `edge_joint` 中存在，并且可运行。** 下列是研究缺陷与性能验收，而不是不存在的功能。

## P0：纠正全系统学习目标

- 在相同部署矩阵、相同请求随机流下，对启发式 S、随机未训练 S、DDQN S 的真实全局 Reward/E2E/截尾作受控对照；S 当前局部阶段负时延信用与 D 总 Reward 并不等价，需找出可能的全局负外部性。
- 不要根据短窗口 censored 编造永久丢包率；统计完成、截尾、截止后补完成和积压。避免 1.01 负载直接被错误解释为无限时延。
- 固定 32 节点、52 连接、10 服务 28 阶段、12,000 用户的现行 benchmark，若恢复原设想 CPU=7200/AP=300/KKT，必须独立重标定并更新物理合同。

## P1：替换未收敛的 Agent-D

D 当前高维长序列 EDIT + REINFORCE 存在非终止、信用方差和后期编辑动作增长。目标是可学习的完整 28×32 合法矩阵分布与安全 FINISH，不使用 PPO、预先候选池、固定副本配额或 Reward 事后矩阵替换。可参考 Masked Discrete SAC 但不能仅替换名称，必须闭合宏/构造双 Q、继承真实后继状态及更新时序。新结构与旧物理引擎必须保持数值一致。

## P2：使长期 KEEP/BUILD 真正有效

当前 `edge_joint.periodic` 已实现同一世界连续多个宏观期的旧矩阵持久化、KEEP/BUILD 宏观学习和 S 调度联训，但尚未提供正式天级连续物理评价，也未学习部署周期长度。需要检查策略何时 KEEP、何时 BUILD、重部署传输/准备/连续性成本是否在当前配置中真实启用与计入。不可把周期数乘短窗长度称为全天仿真。

## P3：正式双种子 64 GS 学习验收

分别验收 D-only、S-only、BUILD-only 联合、多周期联合，每个 64 GS 的含义要明确，真实记录每次完整部署物理评价次数与墙钟。至少每 8 个宏观更新 checkpoint 记录 fixed Reward/E2E/截尾/尾部风险及 D/S 动作变化；最终在完全未见人口/需求测试。原始训练 Reward 逐条无平滑，不删除任何极端负峰。仅选 best/last 保存模型。

## P4：交接质量

新增实验须有复现命令、物理成本预算、独立对照和负结果。禁止再把历史算法直接复制进主代码树；只将新算法放在唯一活动模块。出现训练死循环需要写明，不得以强制终止或虚构 Reward 作为修复。
